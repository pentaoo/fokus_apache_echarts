# Правила поведения графиков

Этот документ фиксирует продуктовую логику прототипа редактора Apache ECharts. Он нужен разработчикам для полного воспроизведения поведения без ручной отрисовки графиков и без изменения пользовательских данных.

## 1. Архитектура и источник истины

- Графики строятся только через Apache ECharts и `vue-echarts`.
- Исходные категории, серии и значения хранятся в состоянии Vue.
- Настройки интерфейса являются единственным источником истины для стилизации.
- Поток синхронизации: `контрол → состояние → CSS-код → ECharts option → график` и обратно `CSS-код → состояние → контрол → ECharts option → график`.
- `applyChartStyle(option, config)` всегда возвращает новый `option` и не мутирует входной объект.
- Некорректное промежуточное значение в редакторе кода не применяется, пока его нельзя безопасно разобрать.
- Переключение типа графика не должно стирать уже введённые данные или сохранённые настройки другого типа.
- При первом запуске таблица содержит две заполненные серии. Все поддерживающие серии графики должны одновременно отображать обе серии.

## 2. Общие правила интерфейса

- В панели показываются только настройки, применимые к активному типу графика.
- Бинарная настройка реализуется нативным `checkbox`, визуально оформленным как switch. Она доступна с клавиатуры и имеет видимый `focus-visible`.
- Если switch открывает зависимые настройки, блок появляется сразу под ним и закрывается при выключении. Состояние вложенных настроек при этом сохраняется.
- Для каждого доступного в новом интерфейсе типа — колонки, строки, линия, круг и кольцо — в секции «Подписи и легенда» есть единый switch «Значения».
- При включении «Значений» сразу под switch раскрываются настройки «Расположение значения» с вариантами «Снаружи» и «Внутри» и «Размер значений». При выключении значения и зависимые настройки скрываются, а выбранные расположение и размер сохраняются в настройках этого типа графика.
- Размер значений регулируется в диапазоне `10–48px`, хранится в `valueLabelSize` и применяется ко всем поддерживаемым типам через `series.label.fontSize`. Slider и процентное поле синхронизированы с этим диапазоном.
- Для числового параметра используются slider и точное числовое поле. Оба контрола работают в одном диапазоне и синхронизируются.
- Составная карточка замыкается радиусом `26px`: верхние углы у первого видимого блока, нижние — у последнего. Между блоками радиус `4px`. Одиночный блок имеет `26px` со всех сторон.
- Интерактивные контролы не должны быть декоративными: каждое изменение преобразуется в валидное поле ECharts `option`.
- Постерный режим отключает интерактивные emphasis/blur/select-эффекты и tooltip. Стандартный режим ECharts продолжает работать независимо.

## 3. Данные и серии

- Категории и серии можно добавлять, переименовывать и удалять в редакторе данных.
- Значение может быть числом или `null`; существующие formatter-функции пользователя сохраняются.
- Line, bar, area, scatter и radar используют все заполненные серии.
- Pie и doughnut отображают одну выбранную серию, а категории становятся секторами.
- Порядок категорий может быть обычным, обратным или зависеть от значения, но сами исходные данные ради сортировки не мутируются.

## 4. Палитры и выбор цвета

- У каждой строки палитры есть цвет и непрозрачность. Видимые текстовые подписи над цветами не выводятся; доступное имя остаётся в `aria-label`.
- Первая серия использует цвет своей строки палитры без затемнения.
- Если серий больше одной, каждая следующая серия использует цвет своей строки и затемняется дополнительно на `20%` относительно предыдущего индекса: серия 2 — на 20%, серия 3 — на 40% и так далее, максимум 90%.
- При раскраске по категориям индекс категории выбирает строку палитры, а затемнение серии применяется поверх выбранного цвета.
- Непрозрачность применяется после затемнения цвета.
- Если цветов больше пяти, color picker открывается рядом с нажатой строкой. Его нижняя граница всегда остаётся внутри нижней границы карточки палитры; при нехватке места picker смещается вверх.
- Color picker повторяет композицию Figma `2238:1041`: карточка `172×236px`, поле насыщенности `164×164px`, hue- и opacity-ряды по `24px`. Слева от hue-track находится увеличенная кнопка пипетки `20×20px` с оригинальной Figma-иконкой.
- Пипетка использует нативный браузерный `EyeDropper API` и запускается только прямым действием пользователя. Выбранный с любой видимой части экрана `sRGBHex` обновляет HEX-поле, HSV-контролы, палитру и график. Отмена системного выбора не меняет цвет; в браузере без `EyeDropper API` кнопка недоступна и объясняет причину через `title`.
- Выбор пресета заменяет палитру, ручное изменение цвета переводит палитру в пользовательский режим.

## 5. Колонки и строки

### 5.1. Общие правила bar

- Направление задаётся стандартной перестановкой category/value axis ECharts; отдельная ручная отрисовка не используется.
- Поддерживаются расположения «Рядом» и «Стопкой».
- Ширина задаётся через `series.barMaxWidth`, расстояние между категориями — через `series.barCategoryGap`, расстояние между сериями — через `series.barGap`.
- Значения снаружи окрашиваются цветом своей серии или категории. Значения внутри всегда белые. В stacked-режиме подпись внутреннего сегмента также белая, даже если общий режим подписей — «Снаружи»; цветной остаётся только текст за внешним краем стопки.
- В режиме строк внутреннее значение всегда находится по центру своего сегмента (`label.position = inside`, `align = center`). Прозрачный горизонтальный padding label равен `16px` слева и справа; отступ не зависит от общего выравнивания текста категории.
- У внешнего значения строки есть левый padding `16px`, поэтому оно не касается скруглённого конца полосы. Если в исходной серии задан собственный padding label, он сохраняется.
- Радиус применяется через `series.itemStyle.borderRadius`.
- В новом интерфейсе slider «Скругление» задаёт коэффициент, а не независимый абсолютный радиус: `0%` — прямой край, `100%` — радиус, равный половине фактической толщины полосы. Фактическая толщина рассчитывается из размера category-band, межкатегорийного и межсерийного расстояния, количества видимых рядом серий и `barMaxWidth`. Поэтому одинаковый процент визуально одинаков для тонких и широких полос.
- При максимальном `barCategoryGap` расчёт радиуса учитывает `barMinWidth`, который ECharts резервирует под включённые подписи значений. Расчётная толщина не может стать нулевой раньше фактической полосы, поэтому увеличение расстояния не выпрямляет уже скруглённые края.
- При stacked-режиме внутренние стыки остаются прямыми. Скругляется только внешний конец всей стопки. Следующий сегмент начинается точно в точке окончания предыдущего, без белого зазора и без наложения скруглённых внутренних углов.

### 5.2. Безопасное расстояние между колонками

- `barCategoryGap = 100%` схлопывает доступную толщину полосы, поэтому интерфейс не допускает значение, при котором внутренняя подпись перестаёт помещаться.
- Максимум вычисляется динамически из размера области графика, числа категорий, числа одновременно расположенных серий, межсерийного расстояния и размера включённых внутренних подписей.
- Если категории подписаны внутри строки, учитывается высота подписи категории.
- Если значения включены и расположены внутри, учитывается высота подписи значения для каждой видимой рядом серии.
- В stacked-режиме при расчёте толщины используется одна суммарная стопка.
- При уменьшении окна, добавлении серии, увеличении шрифта или включении внутренней подписи текущее расстояние автоматически ограничивается новым безопасным максимумом.
- Если внутренних подписей нет, допустим полный диапазон `0–100%`.

### 5.3. Режим «Строки»

- Горизонтальный график занимает всю доступную ширину слайда: `grid.left = 0`, `grid.right = 0`, `grid.width = auto`.
- Категориальная ось строк всегда ограничена реальным диапазоном `0…количество категорий − 1`, поэтому пять строк равномерно занимают всю высоту grid и не сжимаются в верхней половине большого слайда.
- Название категории внутри полосы всегда белое.
- Категориальные подписи строк всегда используют `barCategoryPosition = inside`: при одной полосе или стопке подпись находится внутри полосы, при нескольких сериях рядом — в центре category-band между полосами. Случайная генерация не может вернуть режим «У оси». Цвет подписи принудительно белый через `axisLabel.color`, а `axisLabel.z` располагает её поверх серий.
- В секции «Подписи и легенда» есть switch «Значения».
- При включении «Значений» сразу под switch раскрываются настройки расположения и размера значения.
- При выключении switch подписи значений скрываются, а выбранное расположение сохраняется.

## 6. Линейные графики

- Каждая серия создаёт отдельную ECharts line-series; совпадающие данные не должны приводить к исчезновению одной из линий.
- Категориальная подпись оси X всегда имеет `axisLabel.align = center`, поэтому находится по центру своей точки/значения независимо от случайного выравнивания заголовка.
- Форма линии: резкая, плавная или ступенчатая. Плавный режим использует числовой `series.smooth` и `smoothMonotone = x`; ступени используют `series.step = middle`.
- Текущая плавность постерного режима — `0.5`, стандартного режима — `0.8`. Значение меняется в `styleLineSeries` в `src/chartStyle.ts`.
- Толщина линии ограничена диапазоном `1–120px`; максимальное значение рассчитано на широкую ленту из референса.
- Тип начертания преобразуется в ECharts `lineStyle.type`: обычная, штрихи, точки или штрих-точка.
- Скруглённые концы и соединения задаются `lineStyle.cap = round` и `lineStyle.join = round`.
- Switch «Значения» управляет `series.label.show`. Внешние значения располагаются над своей точкой и всегда выравниваются по её центру; внутренние — в центре точки/линии.
- Если значения включены, а визуальные точки выключены, ECharts получает нулевые символы: это сохраняет штатный anchor для line-label, но не показывает маркеры.
- Точки, их размер, area fill, прозрачность, connectNulls, stack и endLabel управляются только стандартными свойствами ECharts.

## 7. Круговой и кольцевой графики

- Размер задаётся `series.radius`, положение — `series.center`, зазор — `series.padAngle`, скругление — `itemStyle.borderRadius`.
- Switch «Значения» управляет процентами секторов. Внутреннее значение — отдельный прозрачный слой той же ECharts pie-series; оно центрируется по радиусу сектора, ориентируется тангенциально и окрашивается в белый.
- При расположении снаружи название и процент объединяются в один штатный внешний label ECharts. Это позволяет общему алгоритму `avoidLabelOverlap` размещать подпись целиком и не скрывать значение из-за конкуренции двух label-слоёв.
- Несмотря на единый внешний label, название и значение оформляются разными ECharts rich-text токенами: `name.fontSize = pieLabelSize`, `value.fontSize = valueLabelSize`. Поэтому sliders «Размер названий» и «Размер значений» регулируют их независимо и не создают два конкурирующих label-слоя.
- Название категории снаружи использует стандартные `label` и `labelLine` ECharts.
- Минимальная толщина кольца рассчитывается от фактического радиуса, чтобы внутренний процент физически помещался. Максимальная толщина ограничена настройкой прототипа.
- При увеличении размера внутренних значений минимальная толщина кольца также увеличивается: используется не меньше `valueLabelSize + 16px`. Размер pie/doughnut-подписей не имеет отдельного скрытого ограничения и следует общему `valueLabelSize`.
- При случайной генерации для doughnut разрешены только две позиции включённой легенды:
  1. вертикальная колонка слева;
  2. горизонтальная строка сверху.
- Верхняя легенда выбирается только если весь её текст помещается по ширине и не пересекается с коротким заголовком слева. При такой компоновке заголовок принудительно выравнивается влево.
- Если верхняя компоновка небезопасна, выбирается левая легенда.
- Левая или правая легенда не смещает круговую серию: `series.center[0]` всегда равен половине фактической ширины слайда. Ширина боковой легенды симметрично вычитается с обеих сторон только при расчёте максимального радиуса. Поэтому круг и кольцо остаются геометрически по центру, а при нехватке места уменьшаются вместо смещения или наложения на легенду.
- Ручные настройки классического редактора могут использовать другие позиции легенды; ограничение двух вариантов относится именно к случайной генерации doughnut.

## 8. Заголовок, легенда и оси

- Заголовок показывается только при непустом тексте и включённом switch.
- В секции «Подписи и легенда» switch «Заголовок» всегда расположен первым. Он замыкает верхний контур карточки радиусом `26px`; последний switch «Легенда» замыкает нижний контур радиусом `26px`. Раскрытие вложенных настроек между ними не меняет внешние углы карточки.
- Видимость легенды управляется независимо от её позиции.
- Для Cartesian-графиков grid резервирует место под включённую легенду и заголовок.
- Для doughnut применяются дополнительные правила безопасной компоновки из раздела 7.
- Для строчного графика случайная генерация использует только горизонтальную легенду сверху или снизу. Перед верхним размещением код оценивает ширину заголовка и всех элементов легенды на фактическом размере слайда. Верхняя легенда разрешена, только если её левый край остаётся правее заголовка с безопасным отступом; при этом заголовок закрепляется слева. Если места недостаточно, итоговый `option` переносит легенду вниз независимо от ранее сгенерированной позиции.
- Безопасная компоновка строк применяется не только при генерации, но и при каждом вычислении `option`: `legend.top/bottom/left/orient` задаются заново, а `grid.top` и `grid.bottom` резервируют соответствующую строку. Поэтому изменение текста заголовка, названий серий или размера окна не приводит к пересечению.
- Для строк, колонок и линий секция «Оси и сетка» содержит независимые switch «Линии осей», «Засечки» и «Линии сетки». Они управляют `axisLine.show`, `axisTick.show` и `splitLine.show` соответственно.
- Случайная генерация линейного графика не может одновременно выключить линии и точки: после генерации хотя бы один из этих способов отображения данных всегда включён. Пользователь может вручную изменить оба переключателя после генерации.
- У строчного графика категориальная ось всегда получает актуальный массив категорий без числовых `min`, `max` и `interval`. Сетка не наследует фиксированные `width` и `height`, поэтому строки равномерно занимают всю доступную высоту слайда при любой случайной генерации и после изменения размера окна.
- Эти три параметра участвуют в случайной генерации, поэтому каждый сгенерированный вариант можно вручную вернуть к нужному состоянию без повторной генерации.
- Числовая ось поддерживает min, max, interval и formatter. Пользовательский formatter не перезаписывается.

## 9. Случайная генерация

- Единственная кнопка случайной генерации находится справа от заголовка «Тип графика» в панели настроек. Под слайдом отдельная кнопка не дублируется. Видимый текст кнопки — «Случайный», доступное имя — «Случайный график».
- Рандомизация меняет только настройки оформления, не категории и не значения данных.
- Рандомизация не меняет выбранную ориентацию bar-графика. В режиме «Столбцы» остаются вертикальные столбцы, в режиме «Строки» — горизонтальные строки; внутри выбранной ориентации случайно меняется только расположение серий «рядом» или «стопкой».
- Для line в постерном режиме горизонтальные и вертикальные подписи остаются включёнными, легенда располагается сверху.
- Для doughnut позиции легенды ограничены безопасными вариантами «слева» и «сверху».
- Коэффициент скругления активного bar-, pie- или doughnut-графика генерируется заново и сразу отражается в slider, CSS-коде и `itemStyle.borderRadius`.
- Случайные значения slider после генерации проходят те же ограничения, что и ручной ввод.
- Новая палитра содержит достаточно строк для текущего набора категорий/серий.

## 10. Карта настроек в ECharts

| Контрол | Путь в `option` | Типы |
| --- | --- | --- |
| Фон | `backgroundColor` | все |
| Заголовок | `title.show`, `title.text`, `title.left` | все |
| Легенда | `legend.show`, `legend.top/bottom/left/right`, `legend.orient` | все поддерживающие серии |
| Подписи осей | `xAxis.axisLabel`, `yAxis.axisLabel` | line, bar, area, scatter |
| Сетка и оси | `grid`, `axisLine`, `axisTick`, `splitLine` | Cartesian |
| Ширина/зазоры bar | `barMaxWidth`, `barCategoryGap`, `barGap` | bar |
| Радиус bar | `itemStyle.borderRadius` | bar |
| Значения bar | `series.label.show/position` | bar |
| Значения line | `series.label.show/position`, нулевой `symbolSize` при скрытых точках | line |
| Значения pie/doughnut | основной внешний `series.label` или внутренний прозрачный pie-layer | pie, doughnut |
| Плавность line | `series.smooth`, `smoothMonotone` | line, area |
| Начертание line | `lineStyle.width/type/opacity/cap/join` | line, area |
| Область line | `areaStyle.opacity/color` | line, area |
| Кольцо/круг | `radius`, `center`, `padAngle`, `startAngle`, `clockwise`, `roseType` | pie, doughnut |
| Подписи секторов | `label`, `labelLine`, `labelLayout` | pie, doughnut |
| Анимация | `animationDuration`, `animationEasing` и update-варианты | все |

## 11. Ограничения Apache ECharts

- Все визуальные эффекты должны выражаться валидным ECharts `option`. Нельзя подменять график изображением, DOM/SVG/Canvas-рисованием или другой библиотекой.
- Если желаемая геометрия не поддерживается стандартной серией ECharts, выбирается максимально близкий честный вариант без изменения данных.
- CSS оформляет только интерфейс и служит редактируемым представлением настроек; содержимое Canvas/SVG ECharts настраивается через `option`.
