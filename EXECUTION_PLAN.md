# План развития редактора стилизации Apache ECharts

## Контекст

План основан на:

- правках после продуктового ревью;
- текущей реализации на Vue 3, TypeScript, Apache ECharts и `vue-echarts`;
- дизайне левой панели из
  [Figma, узел `45962:7606`](https://www.figma.com/design/yYJeHJba8rZt55UJIvmy4v/%D0%A4%D0%BE%D0%BA%D1%83%D1%81---Fokus?node-id=45962-7606&m=dev);
- ограничениях и критериях готовности из `AGENTS.md`.

Текущая версия уже поддерживает ручную палитру, часть настроек серий,
стандартный и стилизованный режимы, Canvas/SVG и двустороннюю
CSS-синхронизацию. Основные пробелы:

- нет именованных цветовых палитр;
- нет отдельных стилистических пресетов для каждого типа графика;
- подписи управляются недостаточно детально;
- легенда может пересекаться с сериями и значениями;
- не все доступные настройки ECharts выведены в интерфейс;
- мобильная версия имеет горизонтальное переполнение.

## 1. Перестроить модель настроек

Разделить единый `ChartStyleConfig` на типизированные блоки:

- `common` — фон, шрифт, палитра, легенда, tooltip и анимация;
- `axes` — горизонтальная и вертикальная оси, сетка и числовой диапазон;
- `labels` — подписи осей, значения и форматирование;
- `bar`, `line`, `area`, `pie`, `scatter`, `radar`;
- `states` — `emphasis`, `blur` и `select`.

Для каждого типа хранить собственные настройки, чтобы при переключении графика
введённые значения не терялись.

Основные файлы:

- `src/App.vue`;
- `src/chartStyle.ts`.

### Требования к состоянию

- Единственным источником истины остаётся типизированное состояние настроек.
- CSS-код и итоговый ECharts `option` вычисляются из состояния.
- Ручные изменения CSS безопасно обновляют состояние.
- Настройки одного типа графика не перезаписывают настройки другого.
- `applyChartStyle` не мутирует исходный `option`.

## 2. Разделить управление подписями

Убрать общий переключатель «Все подписи».

Новая секция — **«Подписи осей и значений»**.

| Контрол | ECharts option | Применимость |
|---|---|---|
| Горизонтальная ось | `xAxis.axisLabel.show` | line, bar, area, scatter |
| Вертикальная ось | `yAxis.axisLabel.show` | line, bar, area, scatter |
| Значения на графике | `series.label.show` | поддерживаемые серии |
| Названия индикаторов | `radar.axisName.show` | radar |
| Подписи секторов | `series.label.show` | pie, doughnut |
| Линии подписей секторов | `series.labelLine.show` | pie, doughnut |

Дополнительно добавить:

- размер, цвет и насыщенность отдельно для каждой оси;
- поворот подписей;
- отступ подписей от оси;
- положение значений;
- формат чисел: обычный, процентный и сокращённый;
- количество знаков после запятой;
- скрытие пересекающихся подписей через `labelLayout.hideOverlap`, где это
  поддерживается ECharts.

Для pie и radar использовать контекстные названия, потому что у них нет
горизонтальной и вертикальной осей:

- «Подписи секторов»;
- «Названия индикаторов».

## 3. Сделать цветовые палитры

Добавить над ручным редактором палитр набор пресетов:

- Fokus — палитра из макета;
- холодная;
- тёплая;
- контрастная;
- монохромная;
- доступная для распространённых нарушений цветовосприятия;
- пользовательская.

### Поведение палитр

- Выбор пресета копирует цвета в состояние.
- Ручная правка переводит палитру в состояние «Пользовательская».
- Пользователь может добавлять, удалять и переставлять цвета.
- Безопасный диапазон длины палитры: от 1 до 12 цветов.
- Прозрачность остаётся индивидуальной для каждого цвета.
- Палитра применяется через `option.color` и `series.itemStyle`.
- Все цвета и значения прозрачности синхронизируются с CSS-редактором.

## 4. Добавить дефолтные стилистические сетапы

Создать `STYLE_PRESETS_BY_TYPE` для всех поддерживаемых типов.

### Линейный

- плавная линия;
- умеренная толщина;
- точки выключены;
- значения скрыты по умолчанию;
- легенда в выделенной нижней области.

### Столбчатый

- скруглённые вершины;
- зазор в характере Figma;
- значения сверху;
- цвет по категории;
- ограниченная максимальная ширина.

### С областями

- плавная линия;
- полупрозрачная заливка;
- точки выключены;
- значения скрыты по умолчанию.

### Круговой

- подписи снаружи;
- включённые label lines;
- безопасный внешний радиус;
- предотвращение пересечения подписей.

### Кольцевой

- увеличенный внутренний радиус;
- компактные внешние подписи;
- легенда в отдельной зоне.

### Точечный

- контрастные точки;
- умеренная тень;
- значения скрыты по умолчанию;
- tooltip включён.

### Лепестковый

- полупрозрачная область;
- спокойная сетка;
- видимые названия индикаторов;
- ограниченный радиус под легенду.

### Логика применения

Переключение типа не должно каждый раз сбрасывать настройки.

Пресет применяется:

- при первом открытии типа;
- по кнопке «Сбросить стиль типа»;
- при явном выборе пресета.

Случайный стиль остаётся отдельной функцией и не заменяет предсказуемые
дефолтные пресеты.

## 5. Исправить легенду

Текущая легенда закреплена сверху справа и может пересекаться с линиями,
столбцами и подписями значений.

### Новое поведение

- Дефолтная позиция — снизу.
- Доступные позиции: сверху, снизу, справа и слева.
- Настраиваются ориентация, размер маркера, отступ и размер текста.
- При большом количестве серий используется `legend.type: 'scroll'`.
- Для декартовых графиков место резервируется через `grid`.
- Для pie и radar корректируются `center` и `radius`.
- При скрытии легенды зарезервированное место освобождается.

Полностью внешнюю HTML-легенду не добавлять: стандартный ECharts `option`
управляет легендой внутри области графика. Пересечение устраняется выделенной
зоной внутри Canvas/SVG.

## 8. CSS-синхронизация

Для каждой новой настройки добавить машиночитаемую CSS-переменную.

Пример:

```css
.chart-poster {
  /* Подписи осей и значений */
  --chart-show-x-axis-labels: 1;
  --chart-show-y-axis-labels: 1;
  --chart-show-value-labels: 0;
  --chart-x-axis-label-rotate: 0deg;

  /* Легенда */
  --chart-show-legend: 1;
  --chart-legend-position: bottom;
  --chart-legend-font-size: 13px;

  /* Линия */
  --chart-line-width: 4px;
  --chart-line-type: solid;
}
```

Обязательная цепочка:

```text
контрол → состояние → CSS-код → ECharts option → график
CSS-код → состояние → контрол → ECharts option → график
```

Некорректные промежуточные значения игнорируются до безопасного разбора.
Нормализация выполняется после завершения редактирования, без прыжков курсора
и потери текста.

## 10. Ограничения ECharts

Не имитировать функции, которые нельзя честно выразить через стандартный
ECharts `option`.

- ECharts не гарантирует универсальное автоматическое отсутствие пересечений
  всех подписей для любых данных.
- Можно использовать `hideOverlap`, `avoidLabelOverlap`, поворот, форматирование
  и ручное управление позициями, но это не полноценный constraint solver.
- Легенда через стандартный `option` располагается внутри области ECharts.
  Внешнюю HTML-легенду в рамках этой задачи не создавать.
- Произвольные формы серий и ручную отрисовку через Canvas, SVG или DOM не
  добавлять.
- Не менять пользовательские данные ради визуального результата.

## 11. Критерии готовности

- `npm run build` проходит.
- Проверены line, bar, area, pie, doughnut, scatter и radar.
- Каждый новый контрол реально меняет валидный ECharts `option`.
- Работают обе цепочки CSS-синхронизации.
- Настройки сохраняются при переключении типов.
- Пресеты применяются предсказуемо и не меняют данные.
- Стандартный и стилизованный режимы продолжают работать.
- Проверены Canvas и SVG.
- Легенда не перекрывает серии и значения.
- На широком и мобильном экране нет горизонтального переполнения.
- Sticky работает только на широком макете.
- В браузере нет ошибок в консоли.
- `applyChartStyle` не мутирует исходный `option`.
- Пользовательские formatter-функции не удаляются.
